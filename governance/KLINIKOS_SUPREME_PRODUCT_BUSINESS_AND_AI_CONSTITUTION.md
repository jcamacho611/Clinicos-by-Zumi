## 1. The one-sentence company definition

**Klinikos is the governed healthcare operating ecosystem that connects care, clinic operations, workforce, education, capacity, transactions, financial truth, verified relationships and intelligence through one persistent identity and one shared operating network.**

Public positioning remains:

> **Klinikos. The clinic operations ecosystem, powered by Zumi.**

Klinikos is not reducible to an EHR, CRM, staffing marketplace, LMS, telemedicine product, RCM tool, directory or AI chatbot. Those are capabilities inside the ecosystem.

## 2. The two lifecycle chains

### Workforce lifecycle

`DISCOVERY → EDUCATION → PRACTICE/SIMULATION → COMPETENCY EVIDENCE → CREDENTIAL/VERIFICATION → OPPORTUNITY → WORK → EXPERIENCE → PROFESSIONAL GROWTH → INDEPENDENT PRACTICE → CLINIC OWNERSHIP → ORGANIZATION OPERATIONS → NETWORK GROWTH`

### Care / revenue lifecycle

`PATIENT DEMAND → ACCESS → REGISTRATION → SCHEDULING → INTAKE → ENCOUNTER → DOCUMENTATION → ORDERS → RESULTS → FOLLOW-UP → CODING → CHARGE → CLAIM → PAYMENT → RECONCILIATION → OUTCOME → FUTURE CARE`

Grid connects capacity, need and opportunity across both chains. Zumi interprets intent and coordinates authorized work across both chains. Identity, authority, evidence, events and Financial OS preserve truth across both chains.

## 5. Zumi intent model

Zumi normalizes ordinary language internally into a reusable intent frame such as:

- `I AM`
- `I NEED`
- `I HAVE`
- `I WANT TO DO`

The user should not have to learn this taxonomy.

A statement like `I am a physician` creates a **claim**, not professional authority. A statement like `I own ABC Medical` creates an organization-relationship claim, not administrative control.

## 6. One person, one lifelong identity

One person may simultaneously or sequentially be a learner, RN, employee, contractor, Grid participant, patient, caregiver, instructor, provider, clinic owner and organization representative.

Relationships, purpose, privileges, entitlements, location and authority change. The person does not fragment into unrelated identities merely because the product context changes.

## 7. Claim → verification → authority

Permanent law:

`CLAIM != VERIFIED FACT != AUTHORITY`

Authority may depend on combinations of identity assurance, organization membership, profession, license/credential evidence, privilege, location assignment, purpose, consent, delegation/supervision, effective dates and policy.

Neither Zumi nor an external model may manufacture authority.

## 8. Active Experience Envelope

Every authenticated experience is composed from the minimum necessary combination of:

- identity and assurance;
- relationship;
- organization/location;
- profession/role;
- credentials/privileges;
- purpose;
- entitlement;
- current intent;
- active work object;
- patient/case context where authorized;
- policy/jurisdiction;
- time;
- risk.

Keep separate:

`EXISTS != DISCOVERABLE != PROMOTED != ELIGIBLE != ENTITLED != AUTHORIZED != VISIBLE != ACTIONABLE NOW`.

Context switching is a security event. Switching Clinic A → Grid → EDU → Clinic B must recompute data scope, navigation, Zumi context/tools, permissions and audit. Prior PHI or organization state must not bleed across contexts.

## 9. Grid is the universal capacity network

Grid is not a nurse marketplace. It is the shared governed exchange substrate for lawful combinations of people, work, opportunities, organizations, services, capacity, space, equipment/resources, education placements, preceptors, referrals, programs and future policy-governed classes.

Universal expression:

- **I NEED** → demand;
- **I HAVE** → resource/supply/capability.

Lifecycle where applicable:

`DEMAND → DISCOVERY → HARD ELIGIBILITY → MATCH → OFFER → ACCEPTANCE → AGREEMENT → RESERVATION / BOOKING → PAYMENT CONDITION → FULFILLMENT → OBLIGATION → PAYOUT / RECONCILIATION → CLOSED`.

AI may interpret and explain. Deterministic Klinikos policy decides eligibility and authority.

Basic participation should remain free/low-friction where economically and legally appropriate because it creates supply, demand, liquidity, identity, relationships and distribution.

Grid economics are **category-specific**. No universal staffing percentage becomes production law until commercial, employment, marketplace, fee-splitting, tax and state-specific review approves the relevant category. Founding organizations may receive preferential economics after that policy exists. Never hard-code an attractive planning percentage into product truth before approval.

## 11. The doctor conversation is the first clinical acceptance standard

The physician requirement is **one continuous Current Visit**, not a wall of modules.

Canonical provider sequence:

`PATIENT SNAPSHOT → WHAT CHANGED → STAFF HANDOFF → TODAY → CLINICAL → ASSESSMENT & PLAN → ORDERS & RESULTS → DOCUMENTATION & CODING → CLOSE VISIT`

The system should make `INITIAL → PREVIOUS → TODAY` clinically useful where structured evidence exists. AI may summarize a deterministic change set but may not invent one.

The provider should not manually reconstruct a visit by jumping across patient, labs, imaging, referrals, documents, telemedicine, coding and billing modules.

## 12. Telemedicine is encounter modality, not a second chart

Target flow:

`SCHEDULE → INTAKE / READINESS / CONSENT → CURRENT VISIT → VIDEO SESSION → SAME ENCOUNTER → DOCUMENTATION → ORDERS / RESULTS → CODING / BILLING READINESS → FOLLOW-UP → CLOSE`.

The operational telemedicine queue may exist, but the clinical record remains the same governed encounter.

A telemedicine appointment flag does not prove a live video vendor exists. Current external dependency truth remains authoritative.

## 13. Documentation, scribe and coding

Target AI-assisted documentation pipeline:

`AUDIO / DICTATION → TRANSCRIPT → EVIDENCE EXTRACTION → STRUCTURED DRAFT → GAP ANALYSIS → CODE CANDIDATES → HUMAN REVIEW / EDIT → AUTHORIZED SIGNATURE`.

AI never silently invents exam findings, laterality, diagnosis, procedures, history, orders, reviewed results or medical necessity. AI never signs, closes the encounter, submits a claim, marks payment, grants credential validity or changes authority.

Suggested coding remains suggestion until governed human review/acceptance.

## 14. Revenue / Financial OS

Financial truth must keep these distinct:

`ACTIVITY → DOCUMENTATION → CODING → CHARGE → CLAIM → PAYMENT → SETTLEMENT → RECONCILIATION`.

Primary owner question:

> **Where did the money stop?**

Klinikos should surface evidence-backed exceptions such as performed-but-not-charged, signed-but-not-coded, claim-not-accepted, denial unresolved, payment unreconciled and Grid obligation unsettled.

`REDIRECT != PAYMENT`. Internal obligation != external settlement. Browser state never manufactures money truth.

## 15. EDU is the workforce supply engine

EDU follows:

`LEARN → PRACTICE → EVIDENCE → HUMAN REVIEW → COMPETENCY → OPT-IN GRID DISCOVERY → OPPORTUNITY → WORK → EXPERIENCE`.

Training completion, badges and AI feedback never become licensure or professional authority by themselves.

The strategic purpose is to turn learning into evidence-backed workforce capacity and then let work create additional professional/network evidence.

## 16. Network preserves real relationships

Network represents verified relationships created through care, employment, education, referrals, services and capacity. It is not a social feed.

Examples include clinic↔provider, clinic↔employee, clinic↔referral partner, clinic↔lab, school↔employer, learner↔preceptor and organization↔vendor.

Each relationship has explicit parties, purpose, state, effective dates, evidence and authorization implications.

## 18. OpenAI provides intelligence; Klinikos provides authority

Canonical Zumi execution:

`USER INTENT → PRIVACY/SECURITY GATE → ACTIVE EXPERIENCE ENVELOPE → AUTHORIZED CONTEXT BUILDER → TASK CLASSIFICATION → DETERMINISTIC POLICY → ZUMI ORCHESTRATOR → OPENAI WHEN REASONING ADDS VALUE → TOOL PROPOSAL → AUTHORIZATION CHECK → HUMAN CONFIRMATION WHEN CONSEQUENTIAL → DETERMINISTIC BACKEND ACTION → VERIFIED RESULT → AUDIT / PROVENANCE → INTERFACE`.

The model never receives a generic unrestricted database tool. Every tool has a bounded schema, authorization requirement, data-classification rule, audit requirement, idempotency expectation, failure behavior and confirmation policy.

## 20. AI workload routing

Use deterministic software for authorization, known status, calculations, pricing, eligibility, credential truth, payment truth, signatures, consent, tax logic and state transitions.

Use models when reasoning genuinely adds value, including intent resolution, summarization, workflow reasoning, longitudinal narrative, documentation drafting, patient-safe explanation, owner briefing, Grid request preparation, education feedback, document analysis and source-backed public research.

Model selection must be runtime-configurable and based on task class, quality requirement, latency, approved data class and measured cost. Do not fossilize model names from planning documents into permanent architecture.
