# Digital Business & Website Blueprint

Status: GOVERNING DOMAIN BLUEPRINT
Phase: P0/P1

## Purpose

Turn `klinikos.io` into a professional, AI-operated acquisition, qualification, contracting, payment, onboarding and expansion system rather than a static brochure.

## Primary public promise

> **Know what needs to happen next.**

Supporting positioning:

Klinikos connects the work around healthcare so organizations can see what is unfinished, who owns it, where legitimate revenue or capacity may be getting stuck, and what should happen next.

## Operating Map

### Inputs

Collect business/operational information only:

- organization type
- locations
- approximate provider/staff count
- current software categories/vendors if volunteered
- workflow pain
- front-desk/call/scheduling/intake issues
- authorization/referral/documentation/billing friction
- staffing/capacity issues
- implementation urgency
- desired outcome
- current software costs only when user supplies them

Never request PHI or patient-record uploads.

### Output

- plain-English workflow map
- potential continuity gaps based only on supplied data
- current software/vendor stack
- KEEP / CONNECT / ABSTRACT / REPLACE candidates
- potential operational value
- possible savings only from supplied/verified inputs
- what cannot be known yet
- recommended approved next step

- explore EDU

These values are not proof of customer contracts, revenue or current cohort activation.

### Tier expectations

#### Free

Discovery, identity, selected network/education access. No expensive unlimited AI.

#### Clinic Operating Analysis

No-PHI operational analysis, workflow map, fragmentation review, prioritized opportunities and next-step recommendation.

#### Implementation Blueprint

Workflow architecture, integration requirements, rollout sequence, scoped proposal and implementation design.

#### Founding / Implementation

Human-reviewed SOW and implementation project. Price depends on current active offer rules and scope.

#### Core

Target for essential organization operating/Care capabilities with explicit entitlement registry.

#### Growth

Target for broader automation/revenue/growth workflows and higher-value Zumi capabilities.

#### Scale

Target for multi-location, advanced Revenue OS, Grid/Network and governance capabilities.

#### Enterprise

Annual/custom contracting with security/procurement, implementation, SSO, advanced governance, integrations, support and negotiated usage.

Exact feature packaging belongs in the Offer/Entitlement Registry, not this prose document.

## Payment paths

### Self-service

`Offer → CheckoutIntent → Payment Provider → PaymentEvidence → Reconciliation → Entitlement → Receipt/Delivery`

### Enterprise

`Qualification → Proposal → Security/Procurement → MSA/SOW/BAA/DPA as applicable → Signature → Invoice/PO/ACH/payment evidence → Entitlement → Implementation`

Never activate entitlement from browser redirect alone.

- explain Klinikos from approved truth
- build Operating Map

- explain active offers
- answer common objections

## Automated follow-up

Triggers may include:

- Operating Map abandoned
- Map completed, no next step
- checkout started, payment unverified
- proposal sent, no response
- paid customer awaiting onboarding
- onboarding stalled
- first value not recorded
- renewal/expansion milestone

Respect consent, suppression, known bounces, channel preference and frequency caps.
