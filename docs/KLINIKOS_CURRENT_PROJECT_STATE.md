Klinikos is one governed healthcare operating ecosystem, not a set of disconnected modules.

> **Simple above. Powerful below.**

> **The complexity belongs to Klinikos, not to the person using Klinikos.**

## 5. Sunday physician/engineer clinical acceptance

The provider convergence sequence is:

`SCHEDULE → INTAKE → STAFF HANDOFF → CURRENT VISIT → PATIENT SNAPSHOT → WHAT CHANGED (INITIAL / PREVIOUS / TODAY) → TODAY → CLINICAL EXAM / BODY MAP → ASSESSMENT & PLAN → ORDERS & RESULTS → TELEMEDICINE AS SAME ENCOUNTER WHEN APPLICABLE → AI DOCUMENTATION DRAFT → CPT / ICD / MODIFIER SUPPORT → BILLING READY → REVIEW / SIGN / LOCK → CLOSE → FOLLOW-UP`.

Important laws:

- MA/LPN/RN/provider work is distinct;
- authority derives from real context/credentials/privileges/policy, not labels;
- structured longitudinal change is deterministic;
- AI may explain/draft but not invent clinical truth or sign;
- staff handoff is encounter-specific;
- telemedicine is the same encounter model;
- billing readiness follows clinical evidence;
- provider work must remain possible without Zumi.

## 6. Grid target

Grid is one of Klinikos' primary compounding engines and flagship experiences.

It must behave as an actual spatial healthcare exchange using real governed inventory:

`I NEED / I HAVE`
→ requirements
→ hard eligibility
→ real candidate set
→ map/list/inspector
→ request/offer
→ agreement
→ reservation/assignment
→ financial obligation where applicable
→ fulfillment
→ evidence
→ reputation/outcome
→ repeat.

No fake providers, fake clinics, fake pins, fake ratings, fake availability, fake distance, or fake liquidity.

Grid must progressively support healthcare people/work, rooms/chairs/facilities, services, equipment/permitted resources, organization capacity, education seats, placements/preceptors, referrals, diagnostic/appointment capacity, and other lawful healthcare resources.

## 7. EDU target

EDU is an interactive academy/workforce system with distinct learner, instructor/preceptor, and institution experiences.

Virtual Clinic Lab uses synthetic data and mirrors real Klinikos operating logic.

Compounding path:

`EDU → LEARNING → PRACTICE/SIMULATION → COMPETENCY EVIDENCE → HUMAN REVIEW → VERIFIED READINESS WHERE APPLICABLE → GRID → OPPORTUNITY → WORK → EXPERIENCE EVIDENCE → REPUTATION → UPSKILLING`.

## 8. Clinic / organization target

Clinic entry should begin operating diagnosis/value, not pricing explanation.

Zumi helps the clinic express pressure such as scheduling, intake, staffing, EHR/documentation friction, follow-up, referrals, billing/revenue leakage, multi-location coordination, or unused capacity.

Klinikos progressively builds an Operating Map and can convert experienced value into paid assessment/proof/implementation/recurring Clinic OS when appropriate.

Clinic OS should unify organization/location, people/assignments, capacity, patient access, operations, care, workflow, financial truth, Grid, and network relationships without forcing an immediate EHR rip-and-replace.

## 9. Zumi target

Zumi is Klinikos Intelligence and semantic navigation, not authority.

OpenAI/ChatGPT intelligence is the primary current production intelligence direction under the Master Canon, with provider abstraction preserved.

Zumi must:

- understand natural language goals;
- tolerate misspellings, shorthand, abbreviations, incomplete thoughts and speech-to-text errors;
- preserve safe context;
- know the active object/context where authorized;
- route users without requiring product-taxonomy knowledge;
- prepare/summarize/compare/suggest using minimum necessary authorized context;
- ask minimal clarification when ambiguity is consequential;
- use bounded server tools for actions.

Zumi never independently establishes clinical, credential, tenant, payment, legal, consent, or Grid authority.
