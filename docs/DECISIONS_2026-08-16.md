# KLINIKOS — DECISION RECORD — 2026-08-16

Status: `CURRENT DECISION RECORD`

This record captures the major decisions that changed or clarified Klinikos direction on 2026-08-16. It is intentionally explicit so future agents do not resurrect narrower or stale interpretations.

## Product

- Klinikos is the healthcare operating **ecosystem**, not merely clinic software.
- The newest definition centers the full healthcare lifecycle: education, credentials, careers, work, operations, capacity, patient demand, business ownership, networks, transactions, finance and intelligence.
- One persistent identity may hold many roles and evolve through the lifecycle.
- Organization contexts evolve from new practice through Clinic OS, Grid, multi-site, network and enterprise.

## Wiring

- "Wiring" now means complete cross-engine functional chains, not merely links/API connections.
- The canonical wiring path is UI → context → intent → route → authorization/eligibility → engine(s) → real state/workflow → persistence/event → truthful result → audit/financial consequence → next route.
- Pages are surfaces; reusable **routes** are the product journeys.
- Living Home should route users through the ecosystem without requiring them to know module boundaries.

## Living Home / Intelligence

- Living Home remains the operating front door built around **WHAT NEEDS TO HAPPEN?**
- Same-surface transformation is preferred where practical.
- Zumi/Klinikos Intelligence resolves current state, desired state, missing requirements, available routes, authorized actions and next best step.
- Zumi does not become authority for permissions, credentials, payments, clinical decisions, safety or transaction state.

## Ecosystem connections

- Clinic OS may create authorized Grid demand/supply from staffing gaps, unused capacity, referrals and resource needs.
- Grid outcomes may create Clinic OS tasks/follow-up, financial obligations and Insights signals.
- EDU is part of the workforce supply chain, not merely an LMS.
- EDU competency/placement/credential evidence may feed Grid eligibility only when policy permits.
- Patient/Care demand may use Grid capacity only with minimum-necessary privacy and progressive disclosure.
- Shared events/adapters should connect engines where appropriate.

## Grid

- Grid is resource/opportunity/capacity/matching/transaction infrastructure, not just staffing.
- Universal language remains **I NEED / I HAVE**.
- Grid must support multi-party composition.
- Hard eligibility precedes ranking.
- No fake inventory, distance, availability, verification, booking, payout or settlement.

## Financial architecture

- Shared financial semantics are preferred across Grid, Clinic OS, commercial activation and other economic routes.
- Use integer cents.
- Redirect is not payment.
- Booking is not fulfillment.
- Obligation is not payout.
- Settlement requires evidence.

## Pricing / revenue

- Monetization is multi-route: paid operational analysis, implementation/onboarding, Clinic OS subscription, Grid economics where lawful, EDU, network/enterprise, and customer-funded variable usage/add-ons.
- Variable AI, messaging, voice, maps, verification and external API cost should be customer-funded/bounded rather than unlimited founder-subsidized usage.
- Historical broad monthly internal-cost estimates are planning notes, not validated production cost truth.
- Pricing should be based on real delivered outcomes, actual vendor cost, measured usage, entitlement and margin.
- Operational Audit checkout currently points to the known GoDaddy Paylink, but browser return is not payment evidence.

## Design

- The approved cinematic Living Home reference remains the target operating shell, not merely marketing inspiration.
- Converted surfaces use obsidian/black cherry/burgundy/dusty rose/warm ivory rather than reverting to cyan/blue SaaS language.
- Transparent production assets are the preferred brand/rose assets when present.
- The design must project real Clinic OS, Grid, EDU, Care, Billing and Insights state rather than decorative modules.
- Mobile is task-first, not desktop squeezed smaller.

## Architecture migration

- No big-bang rewrite.
- Preserve functioning systems.
- Use adapters, shared services, route definitions, policy modules, events and gradual migration.
- Concurrent agents must fetch/compare/preserve/re-anchor/test/review before merge.
