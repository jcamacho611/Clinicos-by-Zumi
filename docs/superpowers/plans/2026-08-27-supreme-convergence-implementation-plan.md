## Dependency-ordered next slices

### Slice 2 — Grid value → account trigger → identity continuity

**Goal:** A public Grid visitor receives useful browse/match state first, then creates a universal identity only when persistence/action requires it.

**Work:**
- Audit `/grid/browse`, public listing detail, join routes, and login/register continuation.
- Define one server-owned continuation token/record where more context than an allowlisted URL intent must survive without putting private text in URLs.
- Reuse universal identity/account infrastructure.
- Preserve entry source, structured intent, selected safe object ID, and desired next action.
- Do not create role-specific permanent accounts.
- Add tests for return continuity, open-redirect rejection, data minimization, and no raw-prompt persistence in public URL state.

`SCHEDULE → INTAKE → STAFF HANDOFF → CURRENT VISIT → WHAT CHANGED → ASSESSMENT/PLAN → ORDERS/RESULTS → DOCUMENTATION/CODING → BILLING READINESS → CLOSE → FOLLOW-UP`

**Work order:**
1. encounter-specific staff handoff;
2. reusable structured clinical components;
3. deterministic longitudinal change graph;
4. body-map versioning where applicable;
5. order/result/referral projections;
6. authority convergence;
7. coding evidence/support;
8. billing-readiness/revenue-integrity convergence;
9. AI-assisted documentation only after structured truth is stable.
