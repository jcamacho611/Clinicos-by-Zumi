> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Collapse Klinikos repository authority into one detailed current master canon while preserving verified implementation evidence, subordinate specialist detail, and historical provenance.

**Architecture:** `docs/KLINIKOS_MASTER_CANON.md` becomes the sole active product/architecture/business/experience authority. Current code/schema/migrations/tests/runtime remain implementation authority. Existing source-of-truth, architecture, ecosystem, master-specification, and legacy-master files become compatibility/subordinate references instead of competing canons. A machine-readable authority map and agent read-order changes make this discoverable and enforceable.

**Tech Stack:** Markdown, YAML, GitHub repository governance, existing Next.js/TypeScript repository conventions.

**Spec:** `docs/superpowers/specs/2026-08-27-unified-master-canon-convergence-design.md`

## Global Constraints

- Preserve current implementation and open feature branches. Do not rewrite runtime behavior in this docs-governance tranche.
- `docs/KLINIKOS_MASTER_CANON.md` is the only active product/architecture/business/experience canon after convergence.
- Current code/schema/migrations/tests/exact-head verification/runtime remain authoritative for what exists today.
- Specialist documents are subordinate elaboration only and cannot override the master canon.
- Historical documents and old prompts retain provenance only.
- The literal protected interactive journey begins with the protected access/NDA/terms/confidentiality airlock before Living Home/Zumi.
- Do not claim legal enforceability, HIPAA compliance, external integration production status, payment settlement, or deployment state without evidence.
- Keep proprietary logic, prompts, ranking/matching internals, risk/anti-abuse logic, private economics, and unnecessary PHI/PII server-confidential.
- No automated outbound process may send confidential or PHI-bearing attachments without disclosure classification, recipient validation, and the governing human/policy gate.
