## 7. Prototype-to-production law

Prototype copy is a compressed architecture claim.

For every material prototype statement ask:

A beautiful screen is not complete if the underlying business/clinical/financial/network claim is fake.

Design prototypes are visual and interaction references, not a second production runtime. Rebuild their intent semantically in the current application architecture.

## 8. Identity, claims, verification, eligibility, entitlement, authority

Permanent separation:

`IDENTITY != CLAIM != VERIFIED FACT != RELATIONSHIP != ELIGIBILITY != ENTITLEMENT != AUTHORITY`.

A user saying "I am a nurse," "I own this clinic," or "I am the patient's daughter" may establish conversational context only.

Email equality alone is not account-control proof or organization authority.

OrganizationMembership is not automatically a claim, verification, or tenant authority record.

Professional identity does not automatically create activity-specific Grid eligibility or clinical authority.

Subscription/payment does not upgrade identity truth or regulated authority.

Authority may depend on tenant, organization, location, relationship, role, profession, license, credential, privilege, assignment, purpose, consent, patient/case/resource scope, supervision/delegation, effective dates, and policy.

## 12. Grid law

Grid is universal healthcare resource, capacity, opportunity, relationship, and transaction infrastructure.

Universal expression:

- `I NEED` = demand;
- `I HAVE` = resource/supply/capacity.

Grid should be map/list/inspector/action oriented, not a category-card brochure.

No fake providers, fake clinics, fake ratings, fake liquidity, fake pins, fake distances, or fake availability.

Hard eligibility precedes ranking.

Canonical flow:

`NEED / HAVE → STRUCTURED DEMAND / RESOURCE → REQUIREMENTS → HARD ELIGIBILITY → CANDIDATE SET → RANK / EXPLAIN → OFFER / REQUEST → AGREEMENT → RESERVATION / ASSIGNMENT → FINANCIAL OBLIGATION → FULFILLMENT → EVIDENCE → REPUTATION / OUTCOME → REPEAT`.

Keep proprietary ranking/matching/anti-gaming internals server-side.

## 13. EDU / workforce law

EDU is an interactive education, simulation, competency, institutional delivery, career-readiness, and workforce environment, not an LMS brochure.

Learner, instructor/preceptor, and institution experiences are distinct projections.

Virtual Clinic Lab should teach through the same healthcare operating architecture used by real Klinikos workflows with synthetic data.

Compounding path:

`EDU → LEARNING → APPLIED PRACTICE / SIMULATION → COMPETENCY EVIDENCE → HUMAN / INSTITUTIONAL REVIEW → VERIFIED READINESS WHERE APPLICABLE → GRID → OPPORTUNITY → WORK → EXPERIENCE EVIDENCE → REPUTATION → UPSKILLING → MORE OPPORTUNITY`.

Training completion never automatically creates licensure or regulated authority.

## 14. Clinical convergence law

Current Visit is the provider-facing convergence surface.

Doctor/engineer-derived acceptance path:

`SCHEDULE → INTAKE → STAFF HANDOFF → CURRENT VISIT → PATIENT SNAPSHOT → WHAT CHANGED (INITIAL / PREVIOUS / TODAY) → TODAY → CLINICAL EXAM / BODY MAP → ASSESSMENT & PLAN → ORDERS & RESULTS → TELEMEDICINE AS SAME ENCOUNTER WHEN APPLICABLE → AI DOCUMENTATION DRAFT → CPT / ICD / MODIFIER SUPPORT → BILLING READY → REVIEW / SIGN / LOCK → CLOSE VISIT → FOLLOW-UP`.

MA, LPN, RN, NP, PA, physician, therapist, biller, coder, and front-desk experiences must not be collapsed into one generic role where responsibilities differ.

Structured longitudinal change is deterministic clinical truth. AI may summarize it but must not invent it.

Staff handoff is encounter-specific and role-governed.

Signed records do not silently mutate.

Telehealth is an encounter mode, not a second chart.

The provider must still be able to complete the encounter if Zumi is unavailable.

## 15. Financial OS / billing law

Klinikos owns clinical-to-financial workflow truth while integrating regulated external rails.

`CARE → DOCUMENTATION → EVIDENCE → CODING → CHARGE → BILLING READINESS → CLAIM → EXTERNAL RAIL → ACCEPTANCE / REJECTION → ADJUDICATION → REMITTANCE → PAYMENT → RECONCILIATION → REVENUE INTEGRITY`.

Keep separate:

`PRICE != QUOTE != CHARGE != INVOICE != PAYMENT INTENT != PAYMENT EVIDENCE != ENTITLEMENT != OBLIGATION != PAYABLE != PAYOUT != SETTLEMENT != REFUND != RECONCILIATION`.

`REDIRECT != PAYMENT`.

`CLAIM SENT != CLAIM ACCEPTED`.

`CLAIM ACCEPTED != ADJUDICATED`.

`ERA RECEIVED != RECONCILED`.

Never invent external money movement or payer state.

## 16. Confidentiality and browser/server boundary

Permanent boundary:

`BROWSER INTENT / INPUT → AUTHENTICATED SERVER CAPABILITY → SERVER-SIDE POLICY / PROPRIETARY ENGINE → MINIMUM-NECESSARY DTO → BROWSER`.

Assume everything delivered to the browser can be inspected, copied, retained, replayed, diffed, and automated.

Keep server-confidential by default:

- credentials/secrets;
- source where disclosure is unnecessary;
- hidden Zumi prompts/directives/orchestration/model routing;
- Grid ranking/matching/eligibility/anti-gaming internals;
- trust/risk/fraud heuristics;
- proprietary workflow rules/private canonical schemas;
- private pricing/margins/discount strategy;
- unreleased roadmap/business strategy;
- privileged security/infrastructure details;
- non-public counterparties;
- unnecessary PHI/PII/private tenant state.

Founder/internal permission to use confidential material for Klinikos work is not permission to disclose it externally.

## 22. Engineering and merge law

Preserve working systems.

Use:

`FETCH → COMPARE → INSPECT → PRESERVE → RE-ANCHOR → TEST → REVIEW → MERGE`.

Do not mass-merge stale branches or overwrite concurrent work.

Before merge:

1. reconcile current `main`;
2. resolve overlapping active PRs;
3. run applicable schema/migration/type/lint/test/security/build/start gates;
4. run browser/mobile/accessibility checks for user-facing work;
5. verify browser/server confidentiality boundary;
6. verify PR description matches exact head;
7. keep external blockers explicit;
8. merge only when the evidence supports the claims.

Never replace an external blocker with fake success.
